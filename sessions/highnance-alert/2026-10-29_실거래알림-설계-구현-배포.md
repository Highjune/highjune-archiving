## 1. 실현 가능성 파악

### 내용
- rt.molit.go.kr 직접 크롤링은 JSP + jsessionid 구조라 비추천. 사이트 자체가 공공데이터포털 이용을 권장.
- 공공데이터포털 `국토교통부_아파트 매매 실거래가 자료` API(`RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade`)가 같은 원천 데이터. 무료·자동승인, 개발계정 일 10,000건, 활용기간 2026-10-29 ~ 2028-10-29.
- 공개 주기는 "신고 다음 날 공개"가 공식이고 하루 몇 번·몇 시 반영인지는 비공개. 1~2분 폴링은 의미 없고 비용(0원) 대비 15분이 적정.
- 신고 기한 30일 → 전월 계약이 당월에 신고될 수 있으므로 **항상 당월+전월** 조회.

### 결정사항
- 폴링 15분(`POLL_INTERVAL_SEC=900`), 로그로 공개 시각 관찰 후 조정.
- 운영계정 전환 불필요 (하루 192건 사용, 한도의 2%).

## 2. 대상 단지·응답 구조 확인 (실제 API 호출)

### 내용
- 성북구(LAWD_CD=11290) 2026-09: 181건, 2026-10: 76건 조회 성공.
- **한신한진은 API에서 `한신`과 `한진(609-1)` 두 단지로 분리**되어 온다. 둘 다 `umdNm=돈암동`, `jibun=609-1`, 1998년 준공. 9월 11건(해제 1 포함), 10월 1건.
- 응답 20개 항목. `aptDong`·`rgstDate`는 소유권 이전등기 후에만 채워짐(9/29 한신 68.13㎡ 7층 건이 10/22 등기되며 107동 채워진 것 확인). 공급면적·호수는 제공 안 됨.
- 해제 건은 `cdealType=O` + `cdealDay`가 붙은 **별도 행**으로 오고 원 거래 행은 그대로 남음 (한진 9/2 59.58㎡ 19층 9억 → 10/1 해제 사례).

### 결정사항
- 필터는 단지명이 아니라 **법정동 + 지번(돈암동:609-1)**. `TARGETS` 환경변수로 단지 추가 가능.
- 거래 식별 키 `deal_key = sha1(시군구|법정동|지번|단지명|계약일|금액|면적|층|해제여부)`. 동·등기일은 키에서 제외.
- 해제 행이 새로 나타나면 "거래 해제" 알림을 별도로 보낸다.

## 3. 알림 채널·저장소·레포 결정

### 내용
- 카카오 "나에게 보내기"는 본인 1명 전용. 2명(사용자+여자친구)에게 보내려면 각자 카카오 개발자 앱 등록 + 액세스 토큰(6시간)/리프레시 토큰(2개월) 갱신 관리가 필요해 부담이 큼. 카카오 앱 등록 자체는 무료.
- 텔레그램 봇은 토큰 만료 없음, 그룹 1곳에 보내면 멤버 전원 수신.
- 기존 `highnance` 레포는 로컬 전용 개인 재정 대시보드(README "배포하지 않음")라 섞지 않음.

### 결정사항
- 알림: **텔레그램 그룹 `오랑오순`** (chat_id `-5249548271`), 봇 `@highnance_alert_bot`. 이메일·카카오 제외. 여자친구는 초대 링크로 나중에 입장(chat_id 불변).
- 저장: home-mysql에 재테크 공용 스키마 **`highnance`** + 전용 계정, 테이블 접두어 `apt_`.
- 레포: 새 private 레포 `Highjune/highnance-alert`, 파이썬. gh CLI에 Highjune 계정이 로그인돼 있어 `GH_TOKEN=$(gh auth token --user Highjune)`로 Claude가 직접 생성.
- 첫 실행 처리는 **C안**: 기존 거래는 알림 없이 적재 + 시작 요약 1건.
- 배포는 **B안**: 기존 couponnote 패턴(Jenkins release pollSCM → DockerHub → compose up).

## 4. 구현

### 내용
파이썬 3.12, 의존성 `requests`·`PyMySQL`·`cryptography`. 모듈:
`config`(환경변수) · `models`(Deal, deal_key) · `molit`(API+XML 파싱, 포털 오류 감지) · `targets`(법정동:지번 필터) · `repo`(MySQL) · `telegram` · `messages`(포맷, 억/만 표기) · `poller`(run_once, 의존성 주입) · `main`(루프, 연속 실패 8회 시 장애 알림 1회).

폴링 흐름: 당월+전월 조회 → 필터 → 테이블 비어 있으면 전부 적재(`notified_at=now`) + 요약 발송, 아니면 새 키 insert(`notified_at NULL`)/기존 키는 동·등기일·raw_json·last_seen_at 갱신 → `notified_at IS NULL` 전부 발송(이전 실패분 자동 재시도) → 성공 시 `notified_at` 갱신.

테스트 37개(pytest): 실제 응답 XML 픽스처로 파서·키 안정성·필터 건수(9월 11/10월 1)·메시지 포맷·run_once 분기(첫 실행, 무변화, 신규, 해제, 등기 후 갱신, 중복 행, 텔레그램 실패 재시도, API 실패) 검증. 로컬·Docker 빌드 모두 통과.

### 결정사항
- 스케줄러 라이브러리 없이 `while True: run_once(); sleep`.
- 비밀값은 서버 `.env`에만. 레포엔 `.env.example`.

## 5. 홈서버 준비·배포

### 내용

- 서비스 디렉토리 `/home/highjune/services/highnance-alert/` (`docker-compose.yml`, `.env` 600).
- Jenkins private 레포 접근: 기존 `id_rsa_jenkins`는 tennis-record-k deploy key라 GitHub가 재등록 거부(`key is already in use`) → 서버에서 `~/.ssh/id_ed25519_jenkins_highnance` 생성, highnance-alert에 read-only deploy key 등록.
- Jenkins 관리자 비밀번호를 모르므로 `init.groovy.d/create-highnance-cred.groovy`(레포 `deploy/jenkins/`)로 자격증명 `highjune-github-ssh-highnance` 생성(실행 후 키 파일·스크립트 자가 삭제 확인). 잡은 `deploy/jenkins/job-config.xml`을 `jobs/highnance-alert-pipeline/config.xml`로 투입. Jenkins compose에 `services/highnance-alert:ro` 마운트 추가(백업 `.bak-20261029`) 후 컨테이너 재생성.
- release 푸시 → 빌드 #1 실패 → 수정 → 빌드 #2 성공(21:20) → 컨테이너 기동.

### 결정사항

## 7. 메시지 개선 논의 (미반영)

### 내용

- 등기 전 = 계약 체결·신고까지만 된 상태(잔금·소유권 이전 전, 해제 가능). 2023년 7월부터 집값 띄우기 방지용으로 등기 여부·동 공개.
- 해제 = 신고된 계약 취소. 2021년부터 공개(자전거래 방지).
- 제안한 최종 포맷: 전용 ㎡(평) · 평당가(전용 기준) · 직전 동일면적 대비 증감 · 중개사 소재지 · 매수←매도 구분 · 준공년도 · 토지임대부 · 등기 상태(완료 시 동). 해제는 "계약 → 해제 (n일 후)". 추가로 **등기 완료 알림**(등기일자 채워지면 동과 함께 1줄) 제안.
- 공급면적/평형 표기는 단지 평형표 수작업 매핑 또는 K-apt API 시도 필요.

### 결정사항

## 주요 발견사항

- **Jenkins 함정**: Jenkins 컨테이너가 호스트 docker 소켓을 쓰므로 `docker run -v $PWD:/src`의 `$PWD`(`/var/jenkins_home/workspace/...`)가 호스트 경로로 해석돼 빈 디렉토리가 마운트됨 → `requirements-dev.txt` not found로 빌드 #1 실패. 테스트를 Dockerfile 멀티스테이지 `--target test`에서 돌리도록 변경해 해결.
- GitHub deploy key는 레포당 1곳만. 같은 공개키를 다른 레포에 등록하면 422 `key is already in use`.
- Jenkins 자격증명은 UI 로그인 없이 `init.groovy.d` + 재시작으로 등록 가능(컨테이너 root 접근 전제).
- Alloy가 `loki.source.docker`로 전체 컨테이너 로그를 수집하므로 highnance-alert 로그는 Grafana/Loki에서 바로 조회 가능.
- 맥북→홈서버 SSH가 한 번 banner exchange 타임아웃(일시적 네트워크), 재시도로 해결. 재시도 전 443·22 포트 확인으로 서버 생존 판단.
- 공공데이터 키·텔레그램 봇 토큰이 대화에 노출됨. 서버 `.env`에만 두었고 레포·문서엔 없음. 재발급은 사용자 선택.
