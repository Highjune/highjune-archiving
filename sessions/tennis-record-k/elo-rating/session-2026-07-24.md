## 3. 8번 시즌('2026 4월~6월') 마감 — 오염 발견 및 복구 (핵심)
7월에 시즌 자동전환이 안 돼서 **7월 경기 25건(유효)이 season_id=8로 잘못 태깅** → 8번 마감 집계가 오염됨.

복구 절차(전부 하나의 트랜잭션, 사용자가 직접 SQL 실행):
1. 오염 마감 롤백: `DELETE player_season_stats WHERE season_id=8`, `DELETE player_season_division WHERE season_id=9`
2. 7월 경기 이동: `UPDATE records SET season_id=9 WHERE season_id=8 AND created_at>='2026-07-01'` (30건)
3. 8번 stats 재집계 (순수 4~6월 122경기)
4. 승강 재판정 (아래) → 플래그 UPDATE
5. 9번 조편성 재생성 (앱 로직 `insertNextSeasonDivisions` 기준, 시드 A고정 절 포함)
6. 검증 후 `COMMIT` (autocommit off로 앱이 못 보던 것도 해결)

**최종 승강 (7월 제외, 4~6월 기준):**
- 승격(B→A): 김지휴·김경헌·최우린 (태진우는 6경기로 최소경기 12 미달 → 최우린으로 대체, 3명 유지)
- 강등(A→B): 김준현·송진용·이강섭 (견우진은 순위 상승으로 잔류, 최윤석 시드 보호)
- 결과 A조 10 / B조 10 균형.
- **시드 규칙**: `is_seeded=1`은 어떤 경우에도 강등 안 됨 (김종규·김태식·최윤석).

## 4. 발견한 이슈 (ELO 전환 때 처리할 것)
- **README.md 마감 쿼리가 낡음**: 하드코딩 승강 2명·시드무시·최소경기 없음.
  실제 앱(`SeasonEndRepository.kt`)은 config `PROMOTION_RELEGATION_COUNT=3`, `SEASON_MIN_GAMES=12`, 시드 처리 있음.
- **강등 판정 버그**: `SeasonEndRepository` relegation이 `division_rank > (비시드수 - n)` 방식인데,
  시드가 상위권에 있으면 순위가 밀려 하위 n명보다 **더 많이 강등**될 수 있음(이번 데이터로 규칙 그대로면 5명 강등).
- **시즌 자동전환 누락**: 6월 말 시즌 전환(is_active 8→9)이 안 일어나 7월 경기가 8번에 쌓임.
  `SeasonEndRepository.switchSeason()`이 있으나 스케줄러가 6월 말에 안 돎.

## 5. ELO 설계 — 진행 중 (내일 이어감)
사용자 제공 룰(요약): 시작 1000 / 팀실력=두 선수 평균 / expected=1/(1+10^((상대-우리)/400)) /
actual=점수차 환산(6점차 완승 1.0, 무 0.5, 6점차 완패 0.0) / delta=32×(actual-expected) /
이긴팀 +delta·진팀 -delta / 참가 시 전원 +1 / 같은 날 여러 경기는 그날 아침 점수 기준 계산 후 하루 끝 일괄 반영.

**A/B조 구분은 폐지 예정.**

기존 데이터 모델: `records`(복식, home/away 각 2명 + team score int + created_at + season_id),
`match_points`(경기당 선수별 ranking_point·is_winner), `players`(is_seeded/is_active/is_guest).
점수차 = home_team_score - away_team_score 로 actual 환산 가능.
