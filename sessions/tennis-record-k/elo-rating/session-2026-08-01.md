## 2. 재계산 개념 (사용자 Q&A로 확정)
- 재계산 = 수동 `/elo/admin`(비번) + 자동 토요일 23시 스케줄러, **둘 다 동일 `recalculateAll()`**.
- **전체 재구축**: `replaceAll` = `deleteAllInBatch()`(elo_history 하드 딜리트) + saveAll. @Transactional 원자적. records(원본)는 안 건드림 → self-healing. 경기 추가/삭제/수정 시 다음 재계산에 자동 교정.
- "오늘 변화"=프리뷰(시뮬), 토요일 밤=공식 확정.

## 3. 배포 (사용자가 베타 MySQL에 직접 적용)
- `elo_history` 테이블 생성 — **FK 제거 버전**(엔티티가 관계 없이 Long 컬럼만 매핑해서 FK 없는 게 코드와 일치). UNIQUE(player_id, calculated_date) + season 인덱스 유지.
- **app_config `config_value` 컬럼 int→VARCHAR(200) ALTER**: 비번 `0522`가 int면 522로 앞0 유실됨. 엔티티는 원래 String이라 VARCHAR가 정석(기존 정수값도 문자열로 잘 동작). **코드 변경 불필요.**
- INSERT: `ELO_RECALC_PASSWORD='0522'`(is_secret=1), `SEASON_PERIOD_MONTHS='3'`.
- 순서: DDL/INSERT 먼저 → 배포 → `/elo/admin`(0522) 재계산 1회 → elo_history 적재.
- `data.sql`(샘플 elo_history+app_config)은 **로컬(H2) 전용** — beta는 MySQL이라 spring.sql.init 기본(embedded-only)상 실행 안 됨. 충돌 없음.
