## 세션 요약

카페(회사 VPN)에서 홈서버 MySQL이 안 붙는 원인을 추적해 "10/15 compose에서 3306을 127.0.0.1로 묶은 것"임을 확인하고, SSH 키 등록 → SSH 터널 접속으로 전환했다. 이어서 ufw 정리·sshd 키 전용·fail2ban을 적용하고, MySQL을 앱 compose에서 분리(`home-mysql`)해 앱 배포가 DB를 재기동하지 않게 했다. 앱 쪽은 6게임 룰 입력 허용(4게임 검증 제거)과 승점 컬럼·메뉴명(시즌 랭킹/전체 랭킹)을 배포했다.

## 2. 홈서버 DB 원격 접속

### 증상·원인
- 카페에서 `snt.o-r.kr:3306` **connection refused** (22/80/443은 정상). refused = 서버까지 도달 후 리스너 없음
- 서버 확인: `tennis-mysql 127.0.0.1:3306->3306` — 10/15 16:54 compose를 `127.0.0.1:3306:3306`으로 수정·재기동한 기록(bash history). 보안 강화로 의도된 변경
### 조치
- 맥북 SSH 키 `ssh-copy-id` 등록 (`!` 실행은 TTY가 없어 실패 → 별도 터미널에서 성공)
- **SSH 터널**로 접속: `ssh -L 13306:127.0.0.1:3306`. DataGrip `snt-외부`는 SSH/SSL 탭 터널 + Host 127.0.0.1로 변경해 접속 성공
- 아키텍처 3종(직접 공개/SSH 터널/개인 VPN) 비교를 archiving README에 문서화 + 아티팩트 도식(https://claude.ai/artifact/FRqHsVXaZTF9GrkGtM6HsD)

## 3. 보안 강화 (서버)

| 항목 | 내용 |
|---|---|
| ufw | 3306·8080·8090·10002·30000 ALLOW 삭제 → **22/80/443만** (docker 공개 포트는 ufw 우회하므로 실질 방어는 바인딩·포워딩) |
| sshd | `/etc/ssh/sshd_config.d/10-key-only.conf`: `PasswordAuthentication no`, `Match Address 192.168.35.0/24`는 비밀번호 허용 |
| fail2ban | sshd jail: 10분 5회 실패 → 1h 차단, 내부망 ignoreip. 설치 직후 봇 실패 17건 관측 |
| 남은 것 | 모뎀·공유기 3306/8080 포워딩 삭제(집에서), root 비밀번호 변경·`root@%` 정리, Tailscale 검토 |

## 4. MySQL compose 분리 (home-mysql)

- 문제: 테니스 Jenkins 배포가 `compose down`을 해서 공유 DB(쿠폰 포함)까지 내려감
- 변경: `services/mysql/docker-compose.yml` 신설(서비스명 `mysql_db` 유지, 컨테이너 `home-mysql`, 비밀번호 `.env`), 테니스 compose는 app만, 쿠폰 compose `DB_HOST=home-mysql`. 볼륨 `snt-record_mysql-data`·네트워크 `snt-record_app-network`는 external
- 실행: 덤프(`~/backup/mysql-all-20261024-1823.sql`)·compose 백업 → `snt-record up -d --remove-orphans`(옛 tennis-mysql 제거) → `mysql up -d` → `couponnote up -d`. 순단 5초
- 검증: 행 수 동일(824/61/622/5/34), 호스트명 해석 OK, 두 사이트 200, 테니스 down/up 시 DB 무영향
- 권한: `tester`에 `coupon.*` ALL 추가 (DataGrip에서 coupon 스키마 조회용). root 비밀번호는 tennis CLAUDE.md 평문에서 알았음 → CLAUDE.md 플레이스홀더화

## 주요 발견사항

- 앱의 글로벌 에러 핸들러가 404도 200으로 응답 → 배포 확인은 콘텐츠로
- Jenkins 잡 2개(`snt-record-pipeline`, `couponnote-pipeline`) 모두 release pollSCM; Jenkins는 docker.sock으로 호스트 도커 직접 조종
- 서버는 WiFi(wlp1s0)로 공유기에 연결 — 유선 권장
- 회사 VPN 상태에선 서버 접속 IP가 AWS 서울(3.39.x)로 찍힘
- 이중 NAT(모뎀 192.168.75.x → 공유기 192.168.35.x). 정전 시 모뎀이 공유기에 주는 IP가 바뀌어 포워딩이 어긋남 → 모뎀 DHCP 예약/브리지/Tailscale로 해결 가능
