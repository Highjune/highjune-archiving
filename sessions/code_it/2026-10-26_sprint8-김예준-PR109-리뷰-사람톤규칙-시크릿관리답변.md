## 3. 멘티 질문 "현업 키 관리" 답변 — 정정과 최종 구조

- 내 첫 답변 "키를 안 만든다"에 사용자 반박("키가 없을 순 없거든") → **AWS 액세스 키 한정**으로 정정. 본질은 "어디에 두고, 어떻게 주입하고, 어떻게 돌리냐".
- 최종 구조: ①보관 Secrets Manager/Parameter Store(KMS 암호화·CloudTrail·IAM 분리·버전) ②주입 ECS `secrets` 필드 valueFrom ③로테이션 ④시크릿 자체 줄이기(IAM Role/OIDC, RDS IAM 인증, Vault dynamic secrets, Sealed Secrets/SOPS)
- 사용자 본인 초안(SM 설명 + KMS 암호문 방식의 로컬 복호화 4단계 + private GitHub yml 레포 방식) 교정: 꼬인 문장 2곳("키들은 전부 다 안되니까요"→"전부 털리니까요", "2..yml"), 마지막 문단에 방식 이름(Spring Cloud Config Server / git submodule) + 평문 git 주의(SOPS/git-crypt), "또 다른 방법" 5종 붙임 문안 제공.
- 회사 방식 참고(일반화): KMS로 암호화한 암호문을 yml에 커밋 → 기동 시 KMS Decrypt(로컬=SSO 자격증명, 운영=IAM 롤). 사내 "KMS Encryption" UI의 4096자 제한 = KMS Encrypt 평문 한도. KMS ≠ Secrets Manager(열쇠 vs 값 보관, SM은 KMS 위에 올라간 윗층).

## 4. (컴팩션 전) 김어진 sprint7 후속 — "롤백 시 log.info는 허위 로그?"

- 결론: 그대로 둬도 됨. @Transactional 커밋은 메서드 리턴 후라 메서드 안 어떤 줄도 커밋 이후일 수 없음 → INFO는 수행 기록이지 커밋 영수증 아님. 롤백 시 전역 핸들러 ERROR가 쌍으로 남아 MDC requestId로 흐름 판독.
- AFTER_COMMIT(@TransactionalEventListener)은 로그가 아니라 부수효과(알림/Kafka/캐시 evict) 전용 — 회사 운영 코드로 검증.
- "로그는 불확실성이 있는 곳에만": 단순 CRUD 완료 안 찍음, 외부 호출 전후 쌍·배치 요약·분기 결정만. 식별자(key=value)가 로그의 본체, 민감정보 금지.
- 사용자 초안 교정 2곳(반대로 읽히는 문장) 후 게시 완료. 후속(로그 형식·식별자 예시) 문안도 전달.
