## 1. 짧은 평 2건 (점수 평가용, 평가체 + 높임말)

- **신상엽**: 스펙 정비 솜씨(Swagger 인터페이스 분리, 검증 메시지·fieldErrors, FE 소스 7천 줄 정리)는 본인 스타일로 자리 잡음. 다만 외부 코드 병합에서 버그를 들여오고 본인이 더 잘 짰던 부분(에러 코드 설계, 핸들러 로깅)이 후퇴 — "가져온 코드와 내 코드를 비교·선택하는 눈" + 미수행 테스트 채우기가 과제. 공백 후 복귀는 긍정적.
- **임아준**: 빈 PR(#98)이라 코드 평가 불가, 이전 제출 이력도 없어 **평가 근거 없음 — 사실 기록으로만**. 카운트 제외 방침과 일관. 코드 올라오면 그때 정식 평가.

## 2. 8기 테스트 철학 — 완전판은 8주제 (총평 5 + 인라인 3)

사용자가 공유용으로 갖고 있던 건 **총평(리뷰 본문) 5주제뿐**이었음. GitHub 원문 재확인 결과(8기 #68/#69/#71/#72 — 4개 PR에 동일 세트):

**총평 5주제** (사용자가 이미 보유):
1. private 메서드 테스트 → 객체 분리 후 public으로 (shoulditestprivatemethods.com)
2. fixture에 빌더 모아두기 비추 (코틀린 가면 default 파라미터로 해결)
3. 테스트 클래스마다 private builder() — 필요한 파라미터만
4. 테스트 data.sql 비추 — given절 파편화로 문서 기능 상실
5. @BeforeEach 기준 2가지 (몰라도 이해 가능 + 수정해도 전 테스트 무영향)

**인라인 3주제** (이번에 추가 확보, 원문 전달 완료):
6. **@WebMvcTest 중복 → ControllerTestSupport 추상 클래스** (#68 — MockMvc/ObjectMapper/@MockitoBean 상위로, 하위는 어노테이션 없이 상속만)
7. **@Transactional 롤백보다 @AfterEach deleteAll** (#68/#69 통합테스트 — 프로덕션의 @Transactional 누락을 테스트 롤백이 가려줌 → deleteAll이면 변경감지가 안 돌아 테스트가 깨지며 실수를 잡음)
8. **@DataJpaTest보다 @SpringBootTest** (#68/#69 — 컨텍스트(컨테이너) 2개 뜨는 비용 > @DataJpaTest 가벼움. Service 테스트하며 Repository도 같이. @DataJpaTest 고집하려면 상위 추상 클래스로. 키워드: "별도의 컨테이너 → 통합 컨테이너")
