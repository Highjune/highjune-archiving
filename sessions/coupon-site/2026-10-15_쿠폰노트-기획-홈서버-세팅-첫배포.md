## 1. 마케팅파트너 가입 유형 조사 (개인 vs 개인사업자)

### 내용
- 컨플 `[26.06] 마케팅파트너 - 가입 사업자 유형 분기 도입`, 재무회계팀 `고액정산자 사업자 전환 논의`, `정산 미결 트래커`, 슬랙 재무회계팀 스레드 조사.
- 개인(PERSONAL): 원천징수 3.3%, 주민번호·계좌는 가입 후 정산 단계 수집, 자동 승인.
- 개인사업자(PRIVATE): 일반과세자만(간이과세자는 `taxType`으로 차단), 세금계산서 발행, 부가세 10% 포함 지급, 사업자등록증·담당자 4종·정산계좌 가입 중 수집.
- **가입 후 유형 변경 불가, 수익 1건이라도 발생하면 전환 불가** → 사업자는 새 이메일로 신규 가입.
- 재무회계팀 의견: 프리랜서는 보통 사업자등록 안 함. 연 4,800만 이하는 부가세 의무 없어 등록 시 오히려 손해.
- 귀속 제외: `@myrealtrip.com` 가입자·법인회원(삼성 등 제휴법인 임직원 계정) 예약은 마이링크 타도 귀속 안 됨. 사내 계정 테스트 건은 정산 제외.
- 정산: 월 10만원 초과 익월 25일, 미만은 6개월 이월. 개인 파트너는 매월 5~10일 파트너페이지 "정산 확인" 필수.
- SNS 주소: 가입 시 URL 형식만 검증(`@URL`), 실제 접속·소유 확인 없음. 등록 채널 90%가 네이버 블로그. 가입 후 파트너페이지에 수정 화면 없음 → `marketing_partner@myrealtrip.com` 메일/젠데스크로 요청(전용 매크로 존재).
- 임직원 겸업 금지 조항은 컨플 취업규칙 본문이 비어 있어 확인 못 함. 슬랙에 MRT 직원 마파 가입 금지 언급 없음.

## 3. 홈서버 아키텍처 문서화·보안 정리

### 내용
- 홈서버: Intel N100 4코어, 16GB(15Gi), NVMe 468GB, Ubuntu, 299일 가동. nginx 1.18(호스트) + docker(snt-app 8090, tennis-mysql 3306, jenkins 18080).
- 실측 외부 포트: 22·80·443 열림, **3306 열림(MySQL 공인 노출)**, 8080 죽은 규칙.
- 조치(SSH 키 등록·sudo NOPASSWD 후 원격 수행):
  - Jenkins `JAVA_OPTS=-Xmx1g -Xms256m` → 4.84GB → 0.44GB
  - nginx `server_name`의 옛 WAN IP `192.168.75.66` 제거
  - tennis-mysql compose `ports` → `127.0.0.1:3306:3306` (외부 `nc` closed 확인, 앱은 docker 네트워크라 무영향)
  - 맥북 `~/.ssh/config`에 `Host snt` 별칭
- 문서: archiving README 요약 구성도 + `home-server-architecture.md`(네트워크·포트·배포·리스크·목표 아키텍처·모니터링 상세) + `nginx-architecture.md`(include 체인·server 블록·certbot·멀티도메인).
- 개념 정리(사용자 질문): 포트 bind/listen은 커널 장부, nginx는 80/443 선점 + Host 분배 + TLS 종료, 포트에 아무도 없으면 커널이 RST, 127.0.0.1=lo 장치, SSH 터널 흐름, 메트릭(pull)·로그(push), Prometheus=숫자 TSDB·Loki=라벨+grep·Grafana=플러그인 클라이언트, PLG 배경.

### 결정사항
- 게이트웨이는 nginx 하나. 모니터링은 Prometheus+Grafana(+Loki). 외부 포트는 22/80/443만. 정전 대비는 일단 무시(무료 운영 우선).
- highjune-archiving = 코드 없는 중계 레포. 홈서버 전체 문서 SSOT는 archiving, tennis-record-k에는 테니스 설계만. sessions도 커밋. PUBLIC이라 비밀정보 금지.

## 5. couponnote 레포 · Spring 뼈대

### 내용
- 처음 Astro 정적 사이트로 뼈대를 만들다 사용자 요청으로 **중단·삭제** → "차라리 Spring + 기존 MySQL coupon 스키마" 방향 확정.
- Spring Boot 4.1.1, Kotlin 2.3, Java 21, Gradle 9.8. 멀티모듈 `api → application → infrastructure → domain → core` (mrt3-ad·marketing-partner·messenger·inapp-message와 같은 방향. payment·settle-v2·partner는 구형 `api→core`).
- 엔티티: Brand, Coupon(kind·code·기간·targetUrl), Article(마크다운), ClickLog(IP SHA-256).
- 페이지: `/`, `/{brand}`(월 자동 제목, 섹션별 쿠폰 표, 만료 자동 숨김), `/{brand}/{slug}`, `/go/{id}`(클릭 기록 → 302, noindex), 404는 HTTP 404. 공정위 문구 전 페이지 고정. Caffeine 5분 캐시.
- `dto`·`client` 모듈(외부 소비자 SDK, RestClient, 자동설정, mavenLocal publish)을 만들었다가 **호출자가 없어 settings에서 주석 처리**(코드 보관, `ApiController.kt.disabled`). 회사 템플릿도 `//include(":dto")`로 비어 있음을 확인.
- 잡은 버그: `@SpringBootApplication` 패키지가 `kr.couponnote.api`라 domain 리포지토리 미탐색 → 루트 패키지로 이동. Thymeleaf에서 `@environment` 빈 접근 금지 → `GlobalModelAdvice`로 모델 주입. Kotlin 중첩 블록주석(`/** /api/** */`) 컴파일 에러.
- 테스트: api 4건 통과. 로컬 jar 실행으로 페이지·302·404 실측.

## 주요 발견사항

- 마케팅파트너 "개인→사업자 전환"은 규정상 불가, 신규 가입만 가능. 간이과세자 가입 불가.
- 파트너페이지는 일반 마이링크 클릭수를 제공하지 않음(다이나믹 배너만). 자체 클릭 로그 + 파트너페이지 "링크 ID별 수익" 엑셀 조인이 전환율 산출의 핵심. 파트너페이지는 공개 포털이라 퇴사와 무관.
- MySQL `0.0.0.0:3306` 바인딩 + 모뎀 포워딩으로 공인 노출돼 있었음 → 바인딩 로컬화로 차단(포워딩 규칙은 집에서 삭제 예정).
- Cloudflare DNS only 레코드 TTL "1" 표시는 Auto의 내부값.
- GitHub deploy key는 레포 간 재사용 불가. public 레포면 익명 HTTPS가 가장 단순.
- 회사 레포 `dto` 모듈은 템플릿 잔재(주석)이며 실제 패턴은 `client` 모듈 안에 DTO 포함(mrt3-payment).
